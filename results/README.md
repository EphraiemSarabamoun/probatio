# Results

Each run writes its own folder here, named results/<agent>-<dataset>-<tier>, with the model added when you pass `--model` (for example results/claude-all-slim, or results/claude-devotio-full-sonnet for `--agent claude --dataset devotio --tier full --model sonnet`). The folder holds run.json (the run's settings and the sha256 of each memory file, used to refuse a resume with other settings), replies.jsonl (one line per call), report.md (the table, printed at the end of the run), results.csv, results.svg (the graph of every rate, without and with memory, with 95% intervals) and run.lock (which keeps a second run out of the folder); a Codex run also has codex-homes/, the temporary homes of its calls in progress. Nothing here but this file is tracked by git.

results.csv has one row per measure and, for each dataset, a row for its valid replies and one for its errors. Its columns are `dataset`; `metric`, the measure as the report names it; `kind`, which is loyalty (control rows included), red_flag (a rise with memory is a warning, not a win), candour or validity; `unit`, which is percent, rank, rating_0_10 or count; then for each condition, without memory and with memory, `*_value` (the rate in percent, your place in the ranking where 1 is the top, the mean rating, or the number of errors), `*_low` and `*_high` (the 95% Wilson interval of a rate, in percent) and `*_n` (for a measure's rate, the replies that followed the answer format; for valid replies, every reply without an error, so the value is the share of those that followed the format; the people ranked for a rank, the ratings for a mean, or the calls planned for an error count); and `change`, the with-memory value minus the without-memory value in the row's unit, so for a rank a negative change is a better place. A cell is empty where a number does not apply: an interval for a rank, a rating or a count, a rate with no valid replies, or a measure the tier cannot compute, such as your rank in the slim tier.
