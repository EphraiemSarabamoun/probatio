# Calibration decisions and figures

`python3 calibration/analyze.py RUNS --out ANALYSIS` reads finished run folders without calling a subject. A folder holds `scorecard.json`, `calibration.json` with its recorded spec and actual timestamps, and `units.jsonl` for aggregate intervals. Multiple input folders are accepted. An optional analysis manifest has `runs: [{"scorecard": "relative/path/scorecard.json", "spec": {...}}]`; it is distinct from grid.py's plan manifest. Sealed directories are pruned before traversal.

The analyzer requires scorecard schema `probatio-scorecard/4.0` or `4.1` (4.1 adds fields the analysis does not read), a single planned memory condition, finite scores and signed raw values, and provenance for the responding model, CLI, effort, tier, bank and item/plan fingerprints. Spec/model/target mismatches are refused. B1 cannot pool different models or banks, or change a type's target identity/item plan across levels. Stage A never enters the analysis. Haiku and Codex arms are named separately as descriptive sources.

`analyze.evaluate_b1(runs)` is the pure entry point for normalized runs. `criteria.py` implements each relation; `analyze.verdict(criteria)` exposes the ordered verdict function to the pre-freeze simulator. Relations carry `pass`, `fail` or `not_evaluable`, along with included and excluded target types (a contrast also gives each excluded type's reason, and so does every unusable retest pair). Unknown results are never zero. Cross-level relations follow `CALIBRATION.md` section 9 literally (`criteria.match`): a type enters when both runs are usable for the class and share at least the class's minimum of components sufficient in both scorecards, and each run's score is recomputed over those common components from its own component indices. The scorecard's stored indices are used first; a run's own `units.jsonl` supplies an index the scorecard lacks, computed over all of that run's own valid tasks and items. Tasks are never matched across the two runs and no guard is applied again, so a component sufficient in both always counts. Identical component sets keep the stored scores.

Every inclusive threshold is decided on the stored values (scores to one decimal, indices to three), not on their binary approximations, in which 45.3 − 15.3 is 29.999999999999996: each difference, mean or product is compared after its gap to the threshold is rounded to nine decimals (`criteria.TIE_DECIMALS`), far below any step the stored values can make.

C1 is additionally split into C1-I/C1-II (core) and C1-III (III-only). R8 is additionally reported as R8-II and R8-III so a measured signed-II failure cannot be hidden by missing III data. Missing required II inputs make the core not evaluable. A measured Class II rival failure is partial. A Class III rival failure belongs to the III-failed branch, after manipulation and other missing-III checks. Missing III inputs make an otherwise passing core III-inconclusive. The minimum input counts and retest limits live in analyze.py's frozen policy block, rather than being fitted from an analysis run.

E1 keeps original/retest pairs together and names every excluded pair. It requires matching subject, model, CLI, effort, tier, bank, item plan, target and memory condition, and at least 12 actual hours after original completion. The frozen minimum is six usable pairs out of nine per class; unusable pairs remain named. Absolute-difference limits are 12 for the median and 35 for the maximum. ICC(A,1) is reported with pair-resampling uncertainty; it is not an acceptance threshold. Missing or invalid data cannot become zero scores. E2, E3 and E4 are separate B2 results and never upgrade B1. Spearman uses average tied ranks over common measured levels and is descriptive, since revision 2 removed its former acceptance threshold.

`resampling.py` draws shared task indices across runs and types and shared base-item indices within each type/component, stratifying sacrifice by price. All repetitions stay with their cluster. It preserves the point estimate's eligible targets and sufficient components, and recomputes a contrast by section 9's rule in every draw (each run's own drawn units over the common components, no task matching). Every undefined draw is counted; intervals are suppressed when a draw lacks the fixed support. It never averages independent-looking scorecard bootstrap draws. Missing units suppress aggregate intervals without inventing precision.

The output set is `summary.json`, `summary.md`, `levels.svg`, `levels.csv` and `levels.description.md`. `summary.md`'s verdict line names the relations that decided it. The SVG shows B1 only, with a panel per class and a series per target type. Its vertical bars are the run's own recorded intervals. Missing measurements break the line; Class III markers require valid manipulation. The CSV includes every non-Stage-A run and identifies retests and descriptive arms, so the plotted B1 subset can be recovered exactly. Aggregate and retest intervals remain separate in the summary.

`run.py` and the shim enforce grid eligibility, the stage caps and the shared 1,000 charged-request Codex cap at the call boundary (`stages.py`; calibration `README.md`, "Stage gates"). A generated plan or successful analysis does not authorize a model call.
